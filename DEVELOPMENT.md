# NickRadar — для разработчиков

Техническая документация: как устроен проект, как запустить локально, тесты и API.
Пользовательское описание сервиса — в [README.md](README.md), выкладывание в интернет — в [DEPLOY.md](DEPLOY.md).

## Как устроено

| Часть | Что делает | Где работает |
| --- | --- | --- |
| Страница (`public/`) | генерация имён, словари, кэш и чёрный список, интерфейс | браузер, отдаётся как статика (Netlify или Vercel) |
| Проверка (`src/`, `api/`, `netlify/functions/`, `server.js`) | отвечает «занято ли это имя» по `t.me` и `fragment.com` | serverless-функции (Netlify или Vercel) либо локальный сервер |

Разделение сделано специально: браузер делает всю состоятельную работу (поиск, словари, кэш),
а серверу остаётся одна stateless-операция — проверить пачку имён. Поэтому не нужны ни база данных,
ни диск, и всё укладывается в бесплатные тарифы хостингов.

## Быстрый запуск

```powershell
cd tg-username-finder
npm start              # http://localhost:3000
```

Зависимостей нет — только Node.js 18+. Если `node` и `npm` не в `PATH` (обычная ситуация на Windows),
запускай `start.cmd` двойным кликом: он сам находит `node.exe`.

Демо-режим без обращения к сети (вердикты выдуманные):

```powershell
start.cmd --mock
```

## Словари

Собираются в два шага (в репозитории лежит только готовый результат для браузера):

```powershell
npm run build:dict      # скачивает english-words и русские существительные в data/
npm run build:webdict   # нарезает их по длинам в public/data/<язык>/<длина>.txt + manifest.json
```

Нарезка нужна, чтобы страница тянула только нужную длину: например, для поиска 8-буквенных слов
загружается один файл на ~450 КБ вместо трёх с половиной мегабайт всех слов.
Отдельно собирается `public/data/blocked.json` — стартовый чёрный список из локального кэша.

## Тесты

```powershell
npm test               # офлайн: генератор имён, кэш/чёрный список, цикл поиска
npm run test:netlify   # Netlify-функции напрямую (с живой проверкой двух имён)
npm run test:smoke     # живой API: нужен запущенный сервер и сеть
```

Дымовой тест умеет работать и против задеплоенного сайта:

```powershell
$env:BASE = "https://nick-radar.netlify.app"; npm run test:smoke
```

## API

- `GET /api/config` — режим и лимиты (фронтенд работает и без него);
- `POST /api/check` — `{name, token?}` — проверка одного имени;
- `POST /api/batch` — `{names: [...], token?}` → `{results, partial}` — проверка пачки (до 20 имён).

Ответы проверки: `free`, `taken`, `collectible` (со `sale` и `details`), `likely-free`, `unverified`.

## Как проверяется занятость

1. **`https://t.me/<имя>`** — есть блок `tgme_page_title` → имя занято; вместо него заглушка
   `tgme_page_icon` → идём дальше.
2. **`https://fragment.com/username/<имя>`** — детальная страница со статусом `Sold` / `On sale` /
   `On auction` / `Available` → имя коллекционное; страница поиска со строкой `Unavailable / Not for sale`
   → имя не коллекционное, то есть подтверждённо свободно.
3. **Bot API `getChat`** — резерв, когда `t.me` недоступен.

> `getChat` сам по себе не годится как основной источник: он **не видит обычных пользователей** и на занятое
> имя отвечает `400 chat not found`. На замерах это давало 5 ложных «свободен» из 24, поэтому его вердикт
> «не найден» никогда не считается доказательством свободы.

## Структура

```
server.js                      локальный сервер: статика + те же /api/*
start.cmd                      запуск двойным кликом (находит node.exe сам)
netlify.toml                   настройки Netlify (publish = public, функции из netlify/functions)
netlify/functions/*.mjs        serverless-функции для Netlify
vercel.json, api/*.js          то же самое для Vercel
src/checker.js                 проверка пачки: общая логика сервера и функций
src/telegram.js                проверка через t.me + резерв Bot API
src/fragment.js                проверка коллекционных имён на fragment.com
src/limiter.js                 ограничитель частоты и пауза при 429
public/index.html              страница: чекер, поиск, как работает, FAQ, контакты
public/styles.css              оформление (тёмная тема, лаймовый акцент, Manrope/Inter/JetBrains Mono)
public/app.js                  интерфейс: поиск, чекер, отрисовка
public/lib/pool.js             генератор кандидатов (браузер + тесты)
public/lib/dictionaries.js     загрузка нарезанных словарей
public/lib/store.js            кэш и чёрный список в localStorage
public/lib/search.js           цикл поиска батчами
public/data/                   словари по длинам + manifest + стартовый чёрный список
public/config.js               адрес API (нужен только если страница живёт на другом домене)
scripts/build-dictionaries.mjs загрузка словарей
scripts/build-web-dicts.mjs    нарезка словарей для браузера
scripts/test-*.mjs             офлайн-тесты
scripts/smoke-test.mjs         дымовой и сквозной тест
tools/mtproto/probe.mjs        опциональная точная проверка через MTProto
```

## Технические ограничения

- **Проверка идёт батчами.** Одна serverless-функция проверяет до 20 имён и живёт считанные секунды,
  поэтому поиск автоматически идёт порциями по 12 имён (~2–5 имён в секунду). За проход реально
  проверить 100–200 имён.
- **Кэш живёт в браузере.** TTL: занятые — сутки, свободные — полчаса, коллекционные — 2 часа,
  чёрный список — месяц.
- **Состояния на сервере нет.** `partial: true` в ответе `/api/batch` означает, что функция не успела
  проверить всё за отведённый бюджет — клиент просто запросит остаток следующим батчем.
- **Разметка `t.me` и `fragment.com` может измениться.** Оба парсера сосредоточены в `src/telegram.js`
  и `src/fragment.js`, тесты на живых страницах — в `scripts/smoke-test.mjs`.
